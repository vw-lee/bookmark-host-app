# AI RULES - DO NOT CHANGE & FOLLOW EVERY SESSION
> v1.13

## Changes and Commits
- Project @README.md file should be the source of truth for all project related information.
- Update project @README.md file for every commit made, including but not limited to: task development, feature update, bug fixes, etc.
- Commit for every change made to the project.
- For serious and large amount of coding work, always consult the user first, clearly state different options with Pros and Cons.

## Project Structure and Documentation
- Project follows a phased development cycle, phases follow numerical order such as 1, 2, 3 etc. Sub-phase tasks follow an alphabetical order, such as a, b, c etc.
- Place a check mark for every project phase and sub-task, tick off when complete.
- Project should be modulized and broken down into maintainable chucks when possible. 
- Each script should ideally not exceed 2000 lines of code, justify with the user if it needs to be. 
- Comments must be included in the code for context, and must be human readable.
- Any decisions that is structral or architectural in nature, always consult the user first.
